# **ADR‑010 — Suffix Schema Formalization**  

#### William Murray  
#### 31 July 2026  
---

### **Status:** Stable  
### **Maintainer:** Corpus Governance Authority  

---

## **1. Context**
The governed corpus uses structured document references of the form:

```
YYYY-NNN-suffix
```

Where:

- `YYYY` is the corpus year  
- `NNN` is the contiguous document index  
- `suffix` is a semantic discriminator identifying the document type  

Suffixes have been used consistently across the corpus (e.g., `meta_spec`, `spec`, `adr`, `notice`, `roadmap`), but until now this schema has been **implicit**, not **normative**.

SC‑TPGM §8 and TST §5.11 mandate tagging consistency, but neither defines the suffix taxonomy.  
This ADR formalizes the suffix schema as a **constitutional identity rule**.

---

## **2. Decision**
The corpus adopts a **normative suffix schema** for all document references.

The following suffixes are formally defined:

| **Suffix**     | **Meaning / Document Type**                                      |
|----------------|------------------------------------------------------------------|
| `meta_spec`    | Constitutional corpus artefacts (e.g., U‑CMS)                    |
| `spec`         | Governed standards (SC‑TPGM, TST, SV‑GOV, etc.)                  |
| `adr`          | Architectural Decision Records                                   |
| `notice`       | Governance notices (e.g., Contributions Disabled)                |
| `roadmap`      | Corpus‑level evolution artefacts                                 |

These suffixes are **mandatory** for all new documents.

Any new suffix requires ADR justification.

---

## **3. Rationale**
Formalizing the suffix schema:

- ensures deterministic document identity  
- eliminates ambiguity in document classification  
- aligns SC‑TPGM §8 with corpus‑level identity governance  
- aligns TST §5.11 with corpus‑level tagging rules  
- enables automated linting and AST validation  
- preserves auditability and traceability  
- prevents accidental mis‑tagging (e.g., TST saved as `002-spec`)  

This ADR resolves the previously implicit convention and elevates suffixes to constitutional status.

---

## **4. Consequences**

### **Positive**
- Document identity becomes machine‑verifiable  
- Corpus registry becomes fully deterministic  
- Standards, ADRs, notices, and roadmap entries become structurally distinguishable  
- Automated CI/CD linting becomes trivial  
- Eliminates accidental duplication or mis‑classification  

### **Negative**
- Existing documents require minor metadata updates  
- SC‑TPGM §8 and TST §5.11 must be amended to reference the suffix schema  

---

## **5. Alternatives Considered**

### **A. Continue using implicit suffixes**  
Rejected — violates corpus determinism and U‑CMS integrity rules.

### **B. Encode type in the numeric portion (e.g., 1xx, 2xx)**  
Rejected — less expressive, harder to parse, and conflicts with existing corpus structure.

### **C. Use directory structure instead of suffixes**  
Rejected — directory structure is already used for grouping; suffixes govern identity.

---

## **6. Implementation Plan**

1. **Update SC‑TPGM §8**  
   Add §8.4 defining the suffix schema.

2. **Update TST §5.11**  
   Require use of the suffix schema defined in SC‑TPGM.

3. **Update README registry table**  
   Reflect the normative suffix taxonomy.

4. **Update existing documents**  
   Ensure all document references use the correct suffix.

5. **Add suffix validation to corpus linter**  
   Enforce suffix correctness in CI/CD.
